# Security Policy

## Supported Versions

Security fixes are provided for the latest release and the current `main` branch. Older releases or forks are best-effort unless a maintainer explicitly marks them as supported.

## Reporting a Vulnerability

Please use GitHub private vulnerability reporting for suspected vulnerabilities. Do not open a public issue for security-sensitive reports.

To submit a report:
- Go to the repository's **Security** tab.
- Click **Report a vulnerability** to open a private advisory draft.

Include:
- Affected version or commit SHA.
- Deployment environment (Operating system, Python version, PyMuPDF / OpenCV versions).
- Clear reproduction steps or proof-of-concept.
- Expected impact.
- Any relevant terminal logs with sensitive data redacted.

**Public Safety Guidance:**
Do not include copyrighted sheet music scans, private student records, or personal directory paths in reports.

If any private credential or sensitive file was accidentally committed, revoke or replace it immediately.
